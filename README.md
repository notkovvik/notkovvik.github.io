# notkovvik.github.io

Персональный сайт-каталог проектов с автоматической загрузкой репозиториев из GitHub.

Живой сайт: https://notkovvik.github.io

---

## Что это

Одностраничный статический сайт, который показывает все публичные репозитории пользователя notkovvik (https://github.com/notkovvik) в виде карточек. Для каждого проекта доступны:

- описание и язык программирования;
- количество звёзд, метки «Архив» и «Форк»;
- ссылка на сайт проекта (если настроен GitHub Pages или указан homepage);
- ссылка на репозиторий;
- кнопка скачивания исходников в ZIP;
- список файлов последнего релиза.

Никакого бэкенда и сборки — только один index.html.

---

## Возможности

- Светлая и тёмная тема (автоматически по системной настройке)
- Поиск по названию, описанию, языку и темам
- Живая статистика: количество проектов, звёзд, языков
- Список файлов последнего релиза с размерами
- Кеширование ответов GitHub API на 10 минут
- Панель диагностики: видно, сколько репозиториев вернул API и какие не найдены
- Адаптивная вёрстка для мобильных устройств
- Доступность: aria-атрибуты, фокус-стили, поддержка prefers-reduced-motion

## Как это работает

Сайт обращается напрямую к GitHub REST API из браузера:

GET https://api.github.com/users/notkovvik/repos?type=owner&sort=updated&per_page=100

Ответ превращается в карточки на клиенте. Никакие данные никуда не отправляются, кроме api.github.com.

---

## Лимиты GitHub API

Без авторизации GitHub даёт 60 запросов в час на IP. Один заход на сайт с пагинацией может съесть несколько запросов, поэтому при активном использовании лимит быстро исчерпывается.

Есть два способа это обойти:

1. Персональный токен GitHub — поднимает лимит до 5000 запросов в час. Токен вводится вручную в панели «Диагностика» на сайте и хранится только в localStorage вашего браузера. Никуда, кроме api.github.com, он не уходит.
2. Кеш на 10 минут — уже встроен, снижает количество запросов при повторных заходах.

### Как создать токен

1. Откройте https://github.com/settings/tokens
2. Generate new token → Fine-grained (безопаснее) или Classic (проще).
3. Для fine-grained: Repository access → нужные репозитории (или все), Permissions → Contents → Read-only.
4. Для classic: поставьте галочку repo.
5. Скопируйте токен и вставьте его в панели «Диагностика» на сайте.

ВНИМАНИЕ: Никогда не вставляйте токен в код сайта. Он попадёт в исходники страницы и будет виден любому через DevTools. Вводите токен только через интерфейс — он сохранится в вашем браузере.

## Приватные репозитории

Публичный GitHub Pages не показывает приватные репозитории. Причины две:

- GitHub API отдаёт приватные репозитории только при наличии токена.
- Токен нельзя встроить в статический сайт — он окажется в открытом доступе.

Если нужно видеть и приватные проекты:

- Локально: откройте index.html на своём компьютере и введите токен — он останется только у вас.
- Публично: сделайте серверless-прокси (Cloudflare Worker, Vercel Function). Токен хранится в переменной окружения на сервере, сайт обращается к прокси, а не к GitHub напрямую.

## Развёртывание

Сайт уже настроен на GitHub Pages.

1. Репозиторий должен называться [ваш никнейм на гитхаб].github.io — тогда сайт откроется по корневому адресу https://notkovvik.github.io/
2. Файл index.html лежит в корне ветки main.
3. В Settings → Pages выбрано: Deploy from a branch → main → / (root).
4. После коммита изменения появляются на сайте через 1–3 минуты.

### Если нужно обновить сайт

1. Отредактируйте index.html прямо на GitHub или через git push.
2. Подождите пару минут.
3. Обновите страницу с Ctrl+F5, чтобы сбросить кеш браузера.

## Настройка

### Изменить имя пользователя

В index.html найдите строку:

const USER='notkovvik';

Замените на нужный логин GitHub.

### Добавить репозиторий в проверку

В функции load() есть массив EXPECTED — в нём перечислены репозитории, которые вы ожидаете увидеть. Если какого-то из них нет в ответе API, он подсветится красным в панели диагностики.

const EXPECTED=['autoinstallermsidrivers'];

### Изменить время кеша

const CACHE_TTL_MS = 10 * 60 * 1000; // 10 минут
